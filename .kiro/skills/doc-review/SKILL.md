# 문서 리뷰 (Doc Review)

5G Security Knowledge Base 문서를 `.kiro/steering/`의 규칙 기준으로 검수한다.
검토 대상(파일/카테고리/전체)은 아래에 지정된다:

$ARGUMENTS

(대상이 비어 있으면 리포지토리 전체 이슈 문서와 SUMMARY.md를 검토한다.)

## 리뷰 절차

1. 검토 대상 문서를 읽는다. 참조 코드 검증이 필요하면 `subject/subject-list.md`를 근거로 사용한다.
2. 아래 체크 항목을 점검한다.
3. **파일을 수정하지 말고**, 위반 사항만 리포트한다. (사용자가 수정을 요청하면 그때 고친다)

## 체크 항목

### A. 구조 / 형식
- [ ] 파일명이 `NN-MM-{Issue_Name}.md` 패턴과 일치 (공백 없이 `_`, 특수문자 정규화: `EAP-AKA_prime`, `IMSI-SUPI`, `HTTP2`, `AI-ML`, `Hardware-Platform`)
- [ ] 제목이 `# NN-MM. {Issue Name}` 형식
- [ ] 10항목 섹션이 순서대로 존재:
  1.개요 2.공격 대상 3.취약점 4.공격 시나리오 5.영향 6.대응 방안 7.3GPP/O-RAN 8.관련 US 9.관련 EU 10.참조 논문

### B. 콘텐츠 품질
- [ ] 핵심 콘텐츠 섹션(2~6)이 참조 나열이 아니라 실제 해설로 채워짐
- [ ] 관점 교차(ENISA=위협지형 / NIST=구현·검증 / CISA·NSA=위협·안보 / 3GPP=표준)가 반영됨
- [ ] 영향(5)이 C-I-A + 프라이버시 관점으로 정리됨

### C. 참조 정확성 (환각 검출)
- [ ] 참조 코드(US-N/EU-N/P-N/TS·TR)가 `subject/subject-list.md` 정의와 일치
- [ ] 존재하지 않는 표준/논문/코드를 지어내지 않았는가
- [ ] 12~15 참조 정의 문서로의 링크가 유효한가

### D. 출처 / 저작권 (steering §6)
- [ ] 외부 원문을 그대로 복사·번역하지 않고 재구성했는가
- [ ] 원문 내용을 옮긴 경우 출처를 명시했는가
- [ ] 원문 요약과 작성자 해설이 구분되는가
- [ ] 기관 로고/제3자 그림을 무단 사용하지 않았는가

### E. 다이어그램 (steering rules-diagrams)
- [ ] 다이어그램은 Mermaid 우선, 권장 타입(sequenceDiagram/flowchart/stateDiagram-v2/classDiagram/erDiagram)만 사용
- [ ] 특수문자 라벨을 따옴표로 감쌌는가
- [ ] SVG는 `.gitbook/assets/`에 두고 상대경로로 참조했는가
- [ ] SVG 파일명이 `{문서파일명}_{설명}.svg` 규칙을 따르는가 (공백 없이 `_`)
- [ ] 다이어그램에 대한 텍스트 설명이 본문에 있는가

### F. 목차 / 링크
- [ ] `SUMMARY.md`에 항목이 존재하고 링크 경로가 실제 파일명(언더스코어 포함)과 일치함 (공백/`%20` 없음)
- [ ] 상호 참조 링크가 실제 파일을 가리킴 (깨진 링크 없음)
- [ ] GitHub/GitBook 양쪽 렌더링 가능한 문법만 사용

## 리포트 형식

파일별로 아래처럼 정리한다:

```
### {파일 경로}
- [심각도] 항목코드: 위반 내용 및 근거
```

- 심각도: **높음**(참조 환각/깨진 링크/구조 누락) / **중간**(콘텐츠 부실/저작권 표기 누락) / **낮음**(스타일/사소한 불일치)
- 위반이 없으면 "✅ 이상 없음"으로 표기한다.
- 마지막에 전체 요약(검토 문서 수 / 심각도별 건수)을 덧붙인다.
