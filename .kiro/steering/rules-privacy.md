# 개인정보·신원 노출 방지 규칙 (Privacy / Identity Protection Rules)

이 저장소는 **공개(public)** 를 전제로 GitHub ↔ GitBook 동기화로 운영된다.
따라서 유지관리자·기여자의 **실제 개인 식별 정보(PII)** 가 어디에도 남지 않도록 강제한다.
AI 에이전트와 사람 기여자 모두 이 규칙을 따른다.
이 파일은 `.kiro/steering/`에 있어 기본 에이전트 세션에 자동 로드된다.

---

## 1. 절대 노출하지 않는 정보 (필수)

아래 정보는 **커밋 메타데이터, 커밋 메시지, 문서 본문, 파일명, 설정 파일, 에이전트 응답(대화)** 어디에도
넣지 않는다. 이미 존재하면 발견 즉시 제거를 제안한다.

- 실제 이름 (예: 성명, 영문 이름)
- 회사/소속 이메일, 개인 이메일 (예: `*@회사도메인`, `*@gmail.com` 등)
- 소속 조직·회사명, 사번, 부서
- 전화번호, 주소, 기타 개인 연락처
- 위 정보를 유추할 수 있는 사용자명·핸들의 실명 매핑

> 허용되는 공개 신원은 **`secututor`** 와 GitHub noreply 이메일 **`secututor@users.noreply.github.com`** 뿐이다.
> (커밋 신원 강제는 `rules-git.md` §4 및 `.githooks/` 참조)

## 2. 에이전트 응답에서의 취급

- 에이전트는 실제 이름/이메일/소속을 **응답 본문에 그대로 되풀이(echo)하지 않는다.**
  - 예: git 로그에서 실제 이메일을 발견해도, 값을 그대로 출력하지 말고
    "비허용 신원이 감지됨" 정도로 **지칭**한다. (조치를 위해 꼭 필요한 최소한만, 마스킹하여 표시)
- 사용자의 PII를 **요약·로그·예시 데이터**에 포함하지 않는다. 예시에는 `secututor`/placeholder를 쓴다.
- 커밋 author 자동 설정 등으로 실제 신원이 감지되면, **값을 노출하지 말고** 사실만 알리고 익명화를 제안한다.

## 3. 커밋·푸시 전 PII 점검 (필수)

커밋/푸시(§ rules-git.md 절차) 직전에 아래를 확인한다.

- [ ] 스테이징된 변경에 실제 이름/이메일/소속/연락처가 없는가 (문서 본문·주석·설정 포함)
- [ ] 커밋 author/committer 가 `secututor <secututor@users.noreply.github.com>` 인가
- [ ] 커밋 메시지에 PII가 없는가
- [ ] 붙여넣은 로그/출력/스크립트에 실제 이메일·경로(사용자 홈 경로의 실명 등)가 섞이지 않았는가

의심되면 커밋하지 말고 **먼저 사용자에게 알리고 정리**한다.

## 4. 발견 시 대응

- 문서/설정 내 PII: 해당 부분을 익명값(`secututor`/placeholder)으로 치환하거나 삭제를 제안한다.
- 이미 커밋된 이력의 PII: 이력 재작성(`filter-branch`/`filter-repo`)이 필요함을 알리고,
  이는 **파괴적 작업**이므로 `rules-git.md` §3에 따라 위험 안내 + 별도 승인 후 진행한다.
  값 자체는 응답에 노출하지 않는다.

---

## 체크리스트

- [ ] 응답/문서/커밋에 실제 이름·이메일·소속·연락처가 없는가
- [ ] 신원은 `secututor` / noreply 이메일로 통일되어 있는가
- [ ] PII 발견 시 값을 노출하지 않고 마스킹/지칭했는가
- [ ] 커밋/푸시 전 PII 점검을 수행했는가 (§3)
